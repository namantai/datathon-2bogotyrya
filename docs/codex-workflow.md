# Работа команды с Codex

## Общий порядок

1. Перед задачей прочитать корневой `AGENTS.md`, проверить ветку и `git status`.
2. Разбить работу на небольшой законченный этап с явными границами и критериями готовности.
3. Для архитектуры, межмодульных контрактов и рискованных изменений сначала подготовить план и оценить влияние на Backend, Frontend, ML и тесты.
4. Изменять только файлы текущей задачи, не затрагивая чужие незакоммиченные изменения.
5. Запустить реально существующие релевантные тесты и сборки, затем проверить итоговый diff и отсутствие секретов/данных.
6. Создавать Pull Request после завершения небольшого проверенного этапа и описывать ограничения честно.

Codex не должен автоматически выполнять commit, push, pull, merge, rebase, force-push, reset, переключение или создание веток. Эти действия выполняются только по явному запросу человека.

## Владение областями

- Fullstack: `backend/`, `frontend/`, HTTP API, файловая обработка, задания, интеграция и инфраструктура.
- ML: `ml/`, данные и разметка, обучение, локальный inference и оценка качества.
- Совместно: `configs/`, контракты и относящаяся к обеим областям документация.

Изменение границы Backend ↔ ML сначала обсуждается обоими разработчиками и фиксируется в `docs/ml-contract.md`. Публичный контракт жюри нельзя менять односторонне.

## Проверки

Backend на текущем этапе:

```bash
cd backend
python -m pytest
```

Frontend на текущем этапе:

```bash
cd frontend
npm run build
```

Перед Pull Request также проверяются `git diff`, `git status`, корневой `.gitignore`, отсутствие ключей, видео, кадров, разметки, весов и локальных артефактов.

## Предпочтения по моделям Codex

Это рекомендации для человека, а не технические требования проекта:

- сложная архитектура: GPT-6.1 Sol / High;
- обычная Fullstack-разработка: GPT-6.1 Sol / Medium;
- сложная интеграция и критический аудит: GPT-6 Astra / High;
- небольшие правки: GPT-6 Luna / Low или Medium.

Доступные модели и настройки могут различаться. Человек выбирает их через интерфейс Codex с учётом сложности и риска задачи.
