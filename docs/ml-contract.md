# DRAFT: внутренний контракт Backend ↔ ML

Статус: **DRAFT — требует согласования Fullstack Engineer и ML Engineer**.

Документ предлагает минимальную границу интеграции и не задаёт архитектуру модели, конкретный framework или список классов нарушений.

## Предложенный интерфейс

```python
def analyze_video(local_video_path: Path) -> AnalysisResult:
    ...
```

Backend использует async service-level `Analyzer`. Подготовлен `LocalProcessAnalyzer`:
доверенный синхронный ML-вызов запускается в отдельном локальном дочернем процессе
на каждое видео. Это не HTTP/межконтейнерный ML-сервис и не реализация модели.
Существующий `create_app(analyzer=...)` остаётся точкой подключения. Реальный модуль,
его лицензии, загрузку весов и итоговый контракт должен подтвердить ML Engineer.

`local_video_path` указывает на локально сохранённый и предварительно проверенный Backend файл. ML-модуль не должен загружать его во внешние сервисы или читать аудио.

## Предложенные структуры

```python
@dataclass(frozen=True)
class Event:
    class_id: str
    start_sec: float
    end_sec: float
    timecode_sec: float
    confidence: float | None
    observation: str
    rule_id: str | None
    evidence_timestamps_sec: list[float]
    conditions: dict[str, bool]


@dataclass(frozen=True)
class AnalysisResult:
    events: list[Event]
```

Семантика полей:

- `class_id`: стабильный внутренний код согласованного класса; неизвестные классы сейчас не фиксируются.
- `start_sec`, `end_sec`: границы события в секундах от начала исходного видео.
- `timecode_sec`: наиболее доказательный момент события.
- `confidence`: необязательная конечная оценка в [0, 1], только если модель её действительно возвращает; калибровка требует согласования. Не определяет юридическую ответственность.
- `observation`: краткое описание только видимых действий, без юридического приговора.
- `rule_id`: необязательная legacy-подсказка, не источник правовой истины. Backend игнорирует её при сопоставлении и ищет нормы в собственном каталоге по `class_id`.
- `conditions`: установленные визуальные boolean-факты. Неизвестное условие отсутствует, а не `false`. Не утверждать невидимые сведения об АБИС, принятии денег или регламентах. До согласования семантики условий передавать `{}`.
- `evidence_timestamps_sec`: 1–3 конечные неотрицательные метки в пределах исходного видео, по которым Backend извлекает реальные JPEG-кадры. Публичный `timestamp_sec` кадра может немного отличаться: Backend возвращает фактический PTS выбранного декодированного кадра, а не копирует запрос ML.

`AnalysisResult(events=[])` означает отсутствие обнаруженных событий. Список может содержать несколько разных событий; правила дедупликации требуют совместного определения.

## Ответственность Backend

- проверить и безопасно сохранить входной файл;
- управлять заданием и тайм-аутом;
- вызвать ML-модуль с локальным путём;
- проверить инварианты результата и преобразовать внутренние ошибки;
- извлечь 1–3 реальных кадра по временным меткам;
- сопоставить `class_id` и установленные условия с версионированным каталогом правил;
- преобразовать внутренний результат в неизменяемый API-контракт жюри.

## Ответственность ML

- выполнить полностью локальный визуальный inference;
- вернуть события с временной локализацией и наблюдаемыми фактами;
- поддержать отсутствие и несколько событий;
- не формировать публичный HTTP-ответ и не придумывать нормативные ссылки;
- не зависеть от фиксированных координат одного ракурса без измеренной проверки.

## Вопросы до утверждения

1. Тип исключений и поведение при недекодируемом видео или внутренней ошибке.
2. Диапазон, смысл и калибровка `confidence`.
3. Инварианты `start_sec ≤ timecode_sec ≤ end_sec` и точность времени.
4. Формат и версионирование `class_id` и `rule_id`.
5. Правила выбора 1–3 кандидатов и дедупликации близких временных меток.
6. Синхронный интерфейс процесса или изолированный worker при измеренной необходимости.

## Точная спецификация подготовленного адаптера

Синхронная функция `analyze_video(local_video_path: pathlib.Path)` возвращает
JSON-совместимый `dict` либо существующий `AnalysisResult` dataclass.
Поле `events` обязательно; `{}`, `None`, ошибка или отсутствие модели никогда
не означают отсутствие нарушений. `{"events": []}` — явный успешный ответ после
проверки всего видео. Лимиты адаптера: 128 событий и 1 MiB JSON, это не требования организаторов.

Пример структуры, не реального наблюдения или утверждённого класса:

```json
{
  "events": [
    {
      "class_id": "CASH_UNSECURED",
      "start_sec": 40.0,
      "end_sec": 46.0,
      "timecode_sec": 44.2,
      "observation": "Синтетическое описание для примера контракта",
      "confidence": null,
      "evidence_timestamps_sec": [44.2],
      "conditions": {}
    }
  ]
}
```

Входные aliases: `code` → `class_id`, `timestamp_seconds` → `timecode_sec`,
`description` → `observation`. Одновременно старое и альтернативное имя не передавать.
Старые поля не переименованы. Отсутствующие `start_sec`/`end_sec` равны `timecode_sec`;
известный интервал обязан содержать таймкод. Времена конечные, неотрицательные,
в секундах от начала **оригинального** видео. После crop/stride/resampling восстановить
исходную шкалу. `confidence`, `rule_id` можно опустить.
Если нет `evidence_timestamps_sec`, Backend берёт кадр по `timecode_sec`.
Сырые картинки/пути `evidence` не принимаются: Backend сам извлекает реальные JPEG,
а не доверяет потенциально подменённым кадрам. Неизвестный класс не отбрасывается:
событие сохраняется с `unknown_event` в нормативных деталях. Дедупликацию разных
наблюдений одного события согласует ML; Backend не объединяет произвольно близкие таймкоды.

## Подключение после согласования (модель сейчас не включена)

1. Отдельно проверить коммерческие лицензии кода и весов. Установить разрешённые
   зависимости, заранее скачать веса в приватный локальный путь. Никаких загрузок
   при inference, аудио, идентификации лиц или облачных AI.
2. Предоставить импортируемый `team_local_inference` с синхронной `analyze_video(Path)`.
   Неполный анализ должен бросать исключение, а не возвращать пустой список.
3. После согласования добавить небольшую factory (пример, не файл проекта):

   ```python
   from fortebank_api.main import create_app
   from fortebank_api.local_analyzer import LocalProcessAnalyzer

   def make_app():
       return create_app(analyzer=LocalProcessAnalyzer("team_local_inference:analyze_video"))
   ```

   Запуск: `uvicorn integration_factory:make_app --factory --workers 1 --no-access-log --no-proxy-headers`.
   `APP_ANALYZER_MODE=disabled` остаётся безопасным default обычного entrypoint;
   инъекция адаптера маркирует UI как `local`. Это **не доказывает готовность/качество модели**.
   Не оборачивать FakeAnalyzer этим адаптером в production.
4. Передавать пути весов через доверенный локальный конфигурационный модуль.
   Child не наследует APP_API_KEY/облачные токены: whitelist PATH/LANG/LC_ALL/TMPDIR,
   Python import path и offline-флаги HF/Transformers.
5. Проверить 0/1/несколько событий, неизвестный класс, отмену, offline, холодный старт
   и полный click-to-result бюджет на целевом оборудовании.

На POSIX отмена убивает process group (SIGKILL), ожидает завершения, затем удаляется
видео. На Windows гарантируется завершение непосредственного child, не дерева.
Модуль — доверенный код, процесс не security sandbox: offline-флаги не блокируют
произвольные сетевые вызовы. Код не должен запускать отделённые daemon-процессы.
Не подключать тяжёлый синхронный inference прямо в async `Analyzer`: он блокирует
event loop и дедлайны. `to_thread` тоже не даёт принудительного завершения потока.

Docker не изменён: ML-модуль и веса в текущий образ не включены. Последующая интеграция
требует согласованной сборки/приватного read-only mount и проверки лицензий.
Linux-контейнер на MacBook не получает PyTorch MPS; CPU/GPU, arm64 и скорость
проверяются отдельно. Межконтейнерный ML-сервис не добавлен.
