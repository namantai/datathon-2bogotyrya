# ForteGuard AI — Frontend

React + TypeScript + Vite. Одна страница: **загрузка → анализ → результат**, либо отдельное состояние ошибки. Светлый фон, белые карточки и малиновые акценты; без истории, настроек, статистики и бокового меню. Это командный прототип, не официальный интерфейс ForteBank. Ориентир — [forte.kz](https://forte.kz/ru), не копия сайта. Разрешённого локального логотипа нет: в шапке один текстовый `ForteBank` рядом с `ForteGuard AI`, без скачанных логотипов/CDN. Макет-картинка к заданию не был приложен.

## Запуск

Требуется Node.js 22.12+ (проверено на 22.22.2), npm и установленные зависимости:

```bash
cd frontend
npm ci
env VITE_UI_MODE=mock npm run dev
```

Откройте http://localhost:5173. Команда выше явно включает **development mock**. Выберите свой **синтетический** `.mov`, затем один из четырёх сценариев: без событий, одно событие, несколько событий, ошибка. Загрузка длится около 0.7 с, затем выполняются два опроса с интервалом 1.5 с. Файл не читается и не отправляется mock-адаптером. Результат не связан с содержимым выбранного файла. Метки и изображения — синтетические; JPEG создаётся из геометрических фигур с заметной подписью прямо в canvas.

`npm run build` создаёт production-сборку с настоящим anonymous-session bridge и без mock, даже при `VITE_UI_MODE=mock`. Экран загрузки появляется сразу; выбор файла доступен после получения серверной сессии/CSRF, запуск анализа — только с допустимым файлом. Ошибка подключения заменяет рабочий экран понятным сообщением и кнопкой явного retry. `npm run preview` не заменяет production reverse proxy; query string или browser storage не включают mock.

## Настоящий Backend: Fish, терминал 2

Терминал 1: запустите FastAPI на `127.0.0.1:8001` по [Backend README](../backend/README.md). В новом терминале из корня проекта:

```fish
cd frontend
npm ci
env VITE_UI_MODE=bridge UI_PROXY_TARGET=http://127.0.0.1:8001 npm run dev
```

Откройте **http://localhost:5173**, без входа, регистрации и кнопки выхода. Не вводите ключ API жюри — он используется только отдельно защищённым API. Выберите синтетический MOV и нажмите «Начать анализ»: загрузка сменится экраном ожидания, затем результатом или ошибкой. Внутренний `job_id` используется для polling, но не занимает отдельную карточку. Кнопка «Проверить другое видео» очищает результат и выбранный файл. При `APP_ANALYZER_MODE=fake` файл действительно загружается и проходит worker, но UI пишет **«Тестовый результат»**, не выдавая заглушку за вывод AI.

Создать MOV без банковских данных (существующий файл не перезаписывается автоматически):

```fish
ffmpeg -v error -f lavfi -i testsrc2=size=160x120:rate=10 -t 3 -an -c:v mjpeg /tmp/forteguard-ui-test.mov
```

| Переменная | Назначение |
|---|---|
| `VITE_UI_MODE` | Только `mock` в dev включает синтетику; default/`bridge` — настоящий Backend. Production всегда bridge. Не секрет. |
| `UI_PROXY_TARGET` | Серверная настройка Vite proxy, default `http://127.0.0.1:8001`; не включается в JS. |

Других frontend env-переменных не требуется. **Никаких секретов в `VITE_*`, frontend `.env` или storage.** Не запускайте Vite из терминала с экспортированными серверными секретами. Браузер обращается к относительным `/ui-api/*` с `credentials: same-origin`, HttpOnly-cookie и CSRF-header; адреса production в JS нет. Vite сохраняет Origin (`changeOrigin: false`), поэтому Backend должен разрешать точный `http://localhost:5173`. При смене hostname/порта также измените Origin Backend, не используйте wildcard.

## Устройство

- `App.tsx`: взаимоисключающие рабочие экраны, перенос клавиатурного фокуса на новый заголовок; однократный bootstrap анонимной сессии, стабильный адаптер, явный retry. StrictMode не дублирует bootstrap.
- `components/UploadCard.tsx`: input, drag-and-drop, замена файла, dev-сценарий.
- `components/AnalysisStatus.tsx`: один показатель `02:32 / 05:00` и одна полоса прошедшего времени, включая upload. Это не процент готовности ML и не фиктивные этапы. Интервал удаляется при смене экрана/unmount.
- `components/Results.tsx`: вердикт, локальный плеер выбранного файла, события, кадры и место для проверенного нормативного источника. Blob URL создаётся только на экране результата, освобождается при reset/unmount; плеер останавливается и сбрасывает source. Неподдерживаемый браузером MOV не мешает изучению кадров.
- `hooks/useAnalysis.ts`: состояния, защита от повторной отправки, отмена, cleanup при unmount/pagehide.
- `lib/analysis.ts`: проверка файла, форматирование, последовательный polling с AbortSignal и общим timeout 5 минут, включая загрузку. Даже зависший адаптер не удерживает UI после таймаута.
- `lib/contracts.ts`: типы и runtime-проверка ответов, ограниченные JPEG data URL, проверка HTTPS-ссылок.
- `services/mock.ts`: только явно выбранный development mock. `services/index.ts` возвращает `null` для автоматического подключения bridge во всех остальных режимах.
- `services/bridge.ts`: настоящий fetch, CSRF, multipart и безопасные HTTP/network-ошибки. Внутренний текст ошибок Backend не показывается как есть.

Клиент проверяет расширение, непустой файл и размер по конфигурации анонимной серверной сессии (default/mock — 128 МиБ, не параметр train). MIME не заменяет расширение; контейнер проверяет сервер. Один файл за раз. Замена/удаление сбрасывает результат. Ошибки не превращаются в вердикт. Polling ограничен 5 минутами с начала upload, запросы сессии — 10 секундами; Backend отдельно ограничивает приём тела 60 секундами. При `429` надо подождать, автоматической повторной отправки файла нет.

Основной таймкод каждого события — один `MM:SS`, без диапазона и дроби. По нажатию плеер переходит к **исходному дробному** `timecode_sec`; до загрузки metadata переход ожидает её появления. Для подписей доказательных кадров сохраняется их собственный точный `timestamp_sec`. Критичность отсутствует в официальном контракте жюри: при наличии приватных метаданных показывается предварительная оценка Backend, иначе «Не определена». Уровень риска не выдумывается. Base64 ограничена эквивалентом JPEG 4 МиБ (Backend default), проверяется синтаксис и JPEG-маркеры. Все строки выводятся средствами React без HTML-инъекций. Нет внешних шрифтов, изображений, аналитики и AI-вызовов.

Bridge использует существующий `GET /ui-api/jobs/{job_id}?include_details=true`, без
дополнительного polling. Старые ответы без метаданных поддерживаются. `failure_reason=timeout`
даёт отдельное сообщение о серверном лимите. Ссылки из `event_details` показываются
только для совпадающего кода события, статуса соответствия `candidate`, правила `verified`,
с заполненными сведениями о проверке и безопасным HTTPS URL. `pending_review`,
`insufficient_data`, `not_applicable` и непроверенные legacy sources не становятся
юридическим основанием. Все текущие реальные записи каталога остаются непроверенными.
Один клиентский таймер использует монотонные часы, не зависит от перевода системного
времени и отклоняет поздний ответ даже при задержке callback браузерного timeout.

По новому UI-заданию отрицательная формулировка — «Нарушения не обнаружены» (в AGENTS.md — «Нарушение не обнаружено»); официальное значение JSON `no_violation` не меняется. Она появляется только после успешного `done` настоящего адаптера, не для fake/demo. Ошибки, timeout и отсутствие модели никогда не превращаются в отрицательный вердикт.

Комплексное ревью после этапа редизайна: **115 Frontend-тестов, 179 Backend-тестов**,
typecheck/build/test:production и HTTP E2E успешны. Браузерная проверка с настоящим
Backend и тестовым анализатором: 0/1/2 события, реальные JPEG, seek, reset, ошибка,

В jsdom canvas подменяется синтетической JPEG-фикстурой: эти тесты не доказывают декодирование JPEG реальным браузером. `test:production` проверяет уже собранный bundle на отсутствие mock-реализации, доступа к защищённому API и browser storage.

При переработке UI: **102 Frontend-теста прошли**, включая новые проверки взаимоисключающих экранов, одной шкалы времени/5-минутного timeout, disabled start, ошибок HTTP, точного seek и освобождения blob/интервалов. ### Воспроизводимая визуальная проверка (только development)

Для браузера без поддержки автоматического выбора файла есть отдельная тестовая страница,
не подключённая к production entrypoint и исключённая из Docker build context:

```fish
# Из frontend/, только синтетика, -n не перезаписывает существующий файл.
mkdir -p tests/tmp
ffmpeg -v error -f lavfi -i testsrc2=size=160x90:rate=10 -t 90 -an -c:v libx264 -pix_fmt yuv420p -movflags +faststart -n tests/tmp/synthetic.mov
npm run dev
```

Откройте `http://localhost:5173/tests/browser-preview.html`. Внизу нажмите
«Подставить синтетический MOV», выберите demo-сценарий и нажмите «Начать анализ».
Проверьте один основной экран, таймкод/seek, reset, ошибку и мобильный viewport.
События этой страницы вымышлены и **не относятся к видео**; кадры явно помечены.
`tests/tmp` и `.mov` игнорируются Git. Страница использует настоящий App и mock-адаптер,
а не отдельную копию интерфейса; её кнопка оснастки не часть продукта.

Для проверки настоящего Backend запустите Vite с `VITE_UI_MODE=bridge` и нужным
`UI_PROXY_TARGET`, разрешите его точный Origin на Backend и откройте эту же страницу
с `?transport=bridge`. Этот параметр существует **только в тестовой HTML-странице**,
не в приложении и не в production. Синтетический файл действительно отправится на
выбранный локальный Backend; не подключайте оснастку к чужим/production заданиям.

Фактически в браузере проверены все четыре экрана, reset и seek к `74.125` секунды
при метке `01:14`, viewport ноутбука и мобильные 390/320 px. В отдельной временной
связке Vite → существующий `tests.http_e2e:create_test_app` → FastAPI/SQLite/worker
проверены ноль/одно/два события и `failed`, реальное декодирование JPEG синтетических
кадров. Использовались отдельная база в `/tmp`, тестовый ключ и только синтетика.
Это подтверждает UI/интеграцию, **не качество настоящей модели**; Safari/iOS/Android
и все возможные MOV-кодеки отдельно не проверялись.

Добавлены только devDependencies: Vitest, Testing Library React/user-event, jsdom и Prettier (для читаемого форматирования), все с MIT-лицензией по установленным package manifests. Лицензии транзитивных пакетов зафиксированы в lockfile; встречаются MIT, MIT-0, ISC, BSD-2/3-Clause, Apache-2.0, BlueOak-1.0.0, CC0-1.0 и CC-BY-4.0. При распространении инструментов сохранять соответствующие notices/атрибуцию. Новых runtime-зависимостей нет.

## Границы TASK 05A и следующий этап

Bridge вызывает общие Backend-сервисы напрямую, не официальный HTTP API с ключом. Реализованы автоматическая короткая анонимная сессия, HttpOnly/SameSite cookie (Secure в production), CSRF/Origin, лимиты bootstrap/upload и доступ только к заданиям своей сессии. Подробные лимиты и ограничения — в Backend README.

Настоящая ML-модель и проверенная нормативная карта не подключены. `ResultViewModel.sources` остаётся внутренней UI-моделью, не расширяющей API жюри; отсутствующее нормативное основание показано явно. Для TASK 05B нужны согласованные ML-контракт, классы/правила, локальный адаптер и проверенные лицензии. В production FakeAnalyzer запрещён, `disabled` заканчивается ошибкой без ложного вердикта. Подключение модели не входит в этот этап.

Production требует HTTPS, раздачи `dist` и проксирования `/ui-api` на одном доверенном origin, секрета API жюри только на сервере и ограничений reverse proxy. Deployment не выполнялся. Истечение/рестарт/очистка cookies закрывают доступ к прежним UI-заданиям, не отменяя worker. Отмена кнопкой прекращает только клиентское ожидание. После refresh сессия восстанавливается, история/файл — нет. Анонимная сессия не обеспечивает персональный аудит: вкладки одного профиля браузера используют общую cookie.

Ручной вход удалён по заданию о FAQ 27. `POST /ui-api/session` с пустым телом выполняется один раз на mount, включая StrictMode; GET сессии отсутствуют. Действующая cookie сохраняет сессию и её TTL. При `401` upload/polling останавливается и один раз запускается автоматический bootstrap, без повторной отправки файла или чтения задания новой сессией. Если bootstrap не удался, есть «Повторить подключение», но нет автоматического retry/polling сессии. Regression tests проверяют 20 rerender, минуту виртуального ожидания, ответы 200/401/429/503, remount и expiry.

Backend теперь очищает старые завершённые результаты по настраиваемому TTL (default 24 часа), не затрагивая активные/недавние; удалённый результат даёт `404`. План same-origin HTTPS и checklist реального браузера: [deployment.md](../docs/deployment.md). Полный отчёт локальных проверок и ограничения: [readiness-report.md](../docs/readiness-report.md).

Реальные HTTP-запросы через Vite + FastAPI проверяет `backend/tests/http_e2e.py` (инструкция в Backend README); React взаимодействия проверяются в jsdom. HTTP-тест не является браузерным E2E. Все данные тестов синтетические. Проверки качества модели, полного SLA и публичного URL ещё предстоят.
