# ForteGuard AI — Frontend, TASK 04

React + TypeScript + Vite. Светлый адаптивный интерфейс с загрузкой MOV, статусом, двумя вердиктами, несколькими событиями и JPEG-кадрами. Это командный прототип, не официальный интерфейс ForteBank.

## Запуск

Требуется Node.js 22.12+ (проверено на 22.22.2), npm и установленные зависимости:

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Откройте адрес Vite (обычно http://127.0.0.1:5173). Выберите свой **синтетический** `.mov`, затем один из четырёх сценариев: без событий, одно событие, несколько событий, ошибка. Загрузка длится около 0.7 с, затем выполняются два опроса с интервалом 1.5 с. Файл не читается и не отправляется mock-адаптером. Результат не связан с содержимым выбранного файла. Метки и изображения — синтетические; JPEG создаётся из геометрических фигур с заметной подписью прямо в canvas.

`npm run build` создаёт production-сборку. В ней mock-модуль исключён, загрузка недоступна и показано ожидание серверного подключения. `npm run preview -- --host 127.0.0.1` позволяет проверить это поведение. Включение mock через environment, query string или browser storage не предусмотрено.

## Устройство

- `App.tsx`: компоновка страницы, загрузка сервисного адаптера.
- `components/UploadCard.tsx`: input, drag-and-drop, замена файла, dev-сценарий.
- `components/AnalysisStatus.tsx`: стадии обработки и ID задания, без выдуманных процентов.
- `components/Results.tsx`: вердикт, события, кадры, место для проверенного нормативного источника.
- `hooks/useAnalysis.ts`: состояния, защита от повторной отправки, отмена, cleanup при unmount/pagehide.
- `lib/analysis.ts`: проверка файла, форматирование, последовательный polling с AbortSignal и общим timeout 5 минут, включая загрузку. Даже зависший адаптер не удерживает UI после таймаута.
- `lib/contracts.ts`: типы и runtime-проверка ответов, ограниченные JPEG data URL, проверка HTTPS-ссылок.
- `services/mock.ts`: только development. `services/index.ts` возвращает `null` в production.

Клиент проверяет расширение, непустой файл и размер до 128 МиБ — это **текущий default Backend**, а не параметр обучающего датасета. MIME не заменяет расширение; проверка контейнера остаётся обязанностью сервера. Один файл за раз. Замена/удаление сбрасывает старый результат. Ошибки не превращаются в успешный вердикт, внутренние исключения не выводятся пользователю.

Таймкоды отображаются как `MM:SS` / `HH:MM:SS` с точностью до миллисекунд; меньшая дробная точность округляется только для отображения. Для кадров используется их собственный `timestamp_sec`. Base64 ограничена эквивалентом JPEG 4 МиБ (Backend default), проверяется синтаксис и JPEG-маркеры, ошибки декодирования браузером дают явную заглушку повреждённого доказательства. Все строки выводятся средствами React без HTML-инъекций. Нет внешних шрифтов, изображений, аналитики и AI-вызовов.

## Проверки

```bash
npm test
npm run typecheck
npm run build
npm run test:production
npm audit --audit-level=high
git diff --check
```

Vitest + Testing Library + jsdom проверяют контракт, пользовательские состояния, все mock-сценарии, недоверенные строки/ссылки, изображения, ошибки, таймаут, отмену, unmount и повторную отправку. В jsdom canvas подменяется синтетической JPEG-фикстурой: эти тесты не доказывают декодирование JPEG реальным браузером. `test:production` проверяет уже собранный bundle на отсутствие mock-реализации, доступа к защищённому API и browser storage.

Добавлены только devDependencies: Vitest, Testing Library React/user-event, jsdom и Prettier (для читаемого форматирования), все с MIT-лицензией по установленным package manifests. Лицензии транзитивных пакетов зафиксированы в lockfile; встречаются MIT, MIT-0, ISC, BSD-2/3-Clause, Apache-2.0, BlueOak-1.0.0, CC0-1.0 и CC-BY-4.0. При распространении инструментов сохранять соответствующие notices/атрибуцию. Новых runtime-зависимостей нет.

## Следующий этап: безопасный bridge

Серверная функциональность в TASK 04 не реализована. До подключения требуется согласовать:

1. Same-origin маршруты UI (пути пока **не утверждены**). Браузер отправляет multipart `file` в bridge, который вызывает обязательные маршруты жюри сервер-сервер с ключом из серверного окружения. Ключ не возвращается в браузер.
2. Защиту bridge: разрешённые пользователи/доступ, CSRF/Origin-проверки, ограничение нагрузки и размеров, ownership заданий. Публичный незащищённый proxy создаст обход авторизации.
3. Реализацию `AnalysisService` с `mode: "bridge"`, безопасным отображением HTTP/network/JSON ошибок, AbortSignal и согласованными лимитами. DTO ответа остаётся неизменным. Никаких `VITE_*` секретов.
4. Отдельный доверенный UI-источник нормативной информации. `ResultViewModel.sources` — лишь предложение внутренней UI-модели, привязанное к индексу события конкретного результата; оно не расширяет API жюри. Нужны согласованная стабильная связь с событием, проверенные название/URL/пункт. Отсутствующий источник сейчас явно отмечен.
5. Сквозную проверку с реальным локальным ML, доказательствами исходного видео, целевым оборудованием и production-сетевой политикой.

Отмена прекращает клиентское ожидание, но не удаляет и не останавливает уже созданное серверное задание. После перезагрузки страницы состояние теряется — история и постоянное хранение не входят в TASK 04.
