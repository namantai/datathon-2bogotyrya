# ForteGuard AI — Frontend

React + TypeScript + Vite. Последовательные экраны загрузки, анализа, результата и ошибки;
плеер исходного файла, переход к событию и JPEG-кадры. Это командный прототип, не официальный интерфейс ForteBank.

В `feature/ml-fixed` перенесён UI из `e4080b4f2acc0606c6a48a6198a3334dbe84857c`
(`origin/feature/fullstack`, также доступен в `origin/main`). Существующий FastAPI
и offline Logistic v4 сохранены. Настройка настоящего анализатора —
[local-ml.md](../docs/local-ml.md). Backend/Docker-реализации из fullstack-ветки
этим переносом не заменяются. Локальные `@types/node` 24 и `types: ["node"]`
сохранены для установленного Node 24; TypeScript-проверка включена.

## Запуск

Требуется Node.js 22.12+ (проверено на 22.22.2), npm и установленные зависимости:

```bash
cd frontend
npm ci
env VITE_UI_MODE=bridge UI_PROXY_TARGET=http://127.0.0.1:8001 npm run dev
```

Откройте http://localhost:5173. Нужен FastAPI на 8001 в режиме `APP_ANALYZER_MODE=local`.
Приложение всегда использует Backend bridge. Устаревшая настройка
`VITE_UI_MODE=mock` больше не включает синтетику. Mock-сервисы остаются только
явными зависимостями тестов, отдельно от обычного запуска приложения.

`npm run build` создаёт production-сборку с настоящим anonymous-session bridge и без mock, даже при `VITE_UI_MODE=mock`. Загрузка доступна после автоматического получения серверной сессии/CSRF; ошибка подключения показана отдельным экраном. `npm run preview` не заменяет production reverse proxy; query string или browser storage не включают mock.

## Настоящий Backend: Fish, терминал 2

Терминал 1: запустите FastAPI на `127.0.0.1:8001` по [Backend README](../backend/README.md). В новом терминале из корня проекта:

```fish
cd frontend
npm ci
env VITE_UI_MODE=bridge UI_PROXY_TARGET=http://127.0.0.1:8001 npm run dev
```

Откройте **http://localhost:5173**, без входа и регистрации. Не вводите ключ API жюри.
Выберите синтетический MOV и нажмите «Начать анализ»: появится отдельный экран
ожидания, затем результат или ошибка. Для следующего файла — «Проверить другое видео».
`job_id` остаётся внутренним идентификатором polling. Настоящий режим — `local`;
при `fake` UI честно показывает тестовый режим, а не AI-вердикт.

Создать MOV без банковских данных (существующий файл не перезаписывается автоматически):

```fish
ffmpeg -v error -f lavfi -i testsrc2=size=160x120:rate=10 -t 3 -an -c:v mjpeg /tmp/forteguard-ui-test.mov
```

| Переменная | Назначение |
|---|---|
| `VITE_UI_MODE` | Устаревшая переменная, не переключает анализатор; приложение всегда использует Backend bridge. |
| `UI_PROXY_TARGET` | Серверная настройка Vite proxy, default `http://127.0.0.1:8001`; не включается в JS. |

Других frontend env-переменных не требуется. **Никаких секретов в `VITE_*`, frontend `.env` или storage.** Не запускайте Vite из терминала с экспортированными серверными секретами. Браузер обращается к относительным `/ui-api/*` с `credentials: same-origin`, HttpOnly-cookie и CSRF-header; адреса production в JS нет. Vite сохраняет Origin (`changeOrigin: false`), поэтому Backend должен разрешать точный `http://localhost:5173`. При смене hostname/порта также измените Origin Backend, не используйте wildcard.

## Устройство

- `App.tsx`: один активный экран; однократный bootstrap анонимной сессии, стабильный адаптер, явный retry подключения при ошибке. StrictMode не дублирует bootstrap.
- `components/UploadCard.tsx`: input, drag-and-drop, замена файла, dev-сценарий.
- `components/AnalysisStatus.tsx`: время ожидания до пяти минут, без выдуманного процента готовности ML.
- `components/Results.tsx`: вердикт, плеер с точным seek, события, кадры, место для проверенного нормативного источника.
- `hooks/useAnalysis.ts`: состояния, защита от повторной отправки, отмена, cleanup при unmount/pagehide.
- `lib/analysis.ts`: проверка файла, форматирование, последовательный polling с AbortSignal и общим timeout 5 минут, включая загрузку. Даже зависший адаптер не удерживает UI после таймаута.
- `lib/contracts.ts`: типы и runtime-проверка ответов, ограниченные JPEG data URL, проверка HTTPS-ссылок.
- `services/mock.ts`: только явная тестовая зависимость. `services/index.ts` всегда выбирает подключение bridge.
- `services/bridge.ts`: настоящий fetch, CSRF, multipart и безопасные HTTP/network-ошибки. Внутренний текст ошибок Backend не показывается как есть.

Клиент проверяет расширение, непустой файл и размер по конфигурации анонимной серверной сессии (default/mock — 128 МиБ, не параметр train). MIME не заменяет расширение; контейнер проверяет сервер. Один файл за раз. Замена/удаление сбрасывает результат. Ошибки не превращаются в вердикт. Polling ограничен 5 минутами с начала upload, запросы сессии — 10 секундами; Backend отдельно ограничивает приём тела 60 секундами. При `429` надо подождать, автоматической повторной отправки файла нет.

Основной таймкод события отображается как `MM:SS`; seek сохраняет исходные дробные
секунды. Для кадров используется их собственный `timestamp_sec`. Base64 ограничена
эквивалентом JPEG 4 МиБ (Backend default), проверяются синтаксис и JPEG-маркеры.
Все строки выводятся React без HTML-инъекций. Внешних AI-вызовов нет.
Новый polling `?include_details=true` совместим с текущим Backend: необязательная
metadata может отсутствовать. Для бинарного v4 остаются `possible_violation`,
«критичность не определена» и отсутствие подтверждённого нормативного основания.

## Проверки

```bash
npm test
npm run typecheck
npm run build
npm run test:production
npm audit --audit-level=high
git diff --check
```

Vitest + Testing Library + jsdom проверяют контракт, пользовательские состояния, все mock-сценарии, недоверенные строки/ссылки, изображения, ошибки, таймаут, отмену, unmount и повторную отправку. В jsdom canvas подменяется синтетической JPEG-фикстурой: эти тесты не доказывают декодирование JPEG реальным браузером. `test:production` проверяет уже собранный bundle на отсутствие mock-реализации, доступа к защищённому API и browser storage.

Добавлены только devDependencies: Vitest, Testing Library React/user-event, jsdom и Prettier (для читаемого форматирования), все с MIT-лицензией по установленным package manifests. Лицензии транзитивных пакетов зафиксированы в lockfile; встречаются MIT, MIT-0, ISC, BSD-2/3-Clause, Apache-2.0, BlueOak-1.0.0, CC0-1.0 и CC-BY-4.0. При распространении инструментов сохранять соответствующие notices/атрибуцию. Новых runtime-зависимостей нет.

## Границы TASK 05A и следующий этап

Bridge вызывает общие Backend-сервисы напрямую, не официальный HTTP API с ключом. Реализованы автоматическая короткая анонимная сессия, HttpOnly/SameSite cookie (Secure в production), CSRF/Origin, лимиты bootstrap/upload и доступ только к заданиям своей сессии. Подробные лимиты и ограничения — в Backend README.

В этой ветке подключён существующий `LocalMLAnalyzer` с Logistic v4. Проверенная
нормативная карта и multiclass-категории моделью не обеспечиваются.
`ResultViewModel.sources` не расширяет API жюри; отсутствующее основание показано
явно. В production FakeAnalyzer запрещён, `disabled` заканчивается ошибкой.

Production требует HTTPS, раздачи `dist` и проксирования `/ui-api` на одном доверенном origin, секрета API жюри только на сервере и ограничений reverse proxy. Deployment не выполнялся. Истечение/рестарт/очистка cookies закрывают доступ к прежним UI-заданиям, не отменяя worker. Отмена кнопкой прекращает только клиентское ожидание. После refresh сессия восстанавливается, история/файл — нет. Анонимная сессия не обеспечивает персональный аудит: вкладки одного профиля браузера используют общую cookie.

Ручной вход удалён по заданию о FAQ 27. `POST /ui-api/session` с пустым телом выполняется один раз на mount, включая StrictMode; GET сессии отсутствуют. Действующая cookie сохраняет сессию и её TTL. При `401` upload/polling останавливается и один раз запускается автоматический bootstrap, без повторной отправки файла или чтения задания новой сессией. Если bootstrap не удался, есть «Повторить подключение», но нет автоматического retry/polling сессии. Regression tests проверяют 20 rerender, минуту виртуального ожидания, ответы 200/401/429/503, remount и expiry.

Backend теперь очищает старые завершённые результаты по настраиваемому TTL (default 24 часа), не затрагивая активные/недавние; удалённый результат даёт `404`. План same-origin HTTPS и checklist реального браузера: [deployment.md](../docs/deployment.md). Полный отчёт локальных проверок и ограничения: [readiness-report.md](../docs/readiness-report.md).

Реальные HTTP-запросы через Vite + FastAPI проверяет `backend/tests/http_e2e.py` (инструкция в Backend README); React взаимодействия проверяются в jsdom. HTTP-тест не является браузерным E2E. Все данные тестов синтетические. Проверки качества модели, полного SLA и публичного URL ещё предстоят.

После результата доступна отдельная авторизованная **ручная проверка**: наблюдаемый
тип, критичность с обоснованием, кандидат нормы и статус записываются отдельно от
автоматического прогноза. Она не возвращает вход перед загрузкой и не требует
ключа API жюри. Настройка reviewer-секретов, ограничения каталога и хранение истории:
[frontend-ml-integration.md](../docs/frontend-ml-integration.md).
