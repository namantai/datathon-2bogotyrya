# ForteGuard AI — Frontend, TASK 05A

React + TypeScript + Vite. Светлый адаптивный интерфейс с загрузкой MOV, статусом, двумя вердиктами, несколькими событиями и JPEG-кадрами. Это командный прототип, не официальный интерфейс ForteBank.

## Запуск

Требуется Node.js 22.12+ (проверено на 22.22.2), npm и установленные зависимости:

```bash
cd frontend
npm ci
env VITE_UI_MODE=mock npm run dev
```

Откройте http://localhost:5173. Команда выше явно включает **development mock**. Выберите свой **синтетический** `.mov`, затем один из четырёх сценариев: без событий, одно событие, несколько событий, ошибка. Загрузка длится около 0.7 с, затем выполняются два опроса с интервалом 1.5 с. Файл не читается и не отправляется mock-адаптером. Результат не связан с содержимым выбранного файла. Метки и изображения — синтетические; JPEG создаётся из геометрических фигур с заметной подписью прямо в canvas.

`npm run build` создаёт production-сборку с настоящим authenticated bridge и без mock, даже при `VITE_UI_MODE=mock`. Без same-origin Backend вход недоступен. `npm run preview` не заменяет production reverse proxy; query string или browser storage не включают mock.

## Настоящий Backend: Fish, терминал 2

Терминал 1: запустите FastAPI на `127.0.0.1:8001` по [Backend README](../backend/README.md). В новом терминале из корня проекта:

```fish
cd frontend
npm ci
env VITE_UI_MODE=bridge UI_PROXY_TARGET=http://127.0.0.1:8001 npm run dev
```

Откройте **http://localhost:5173**, введите отдельный код Web UI, заданный только на Backend. Не вводите ключ API жюри. Выберите синтетический MOV и нажмите «Начать проверку»: появятся `job_id`, статус и результат. Для следующего файла сбросьте результат или замените файл. При `APP_ANALYZER_MODE=fake` UI явно предупреждает: файл действительно загружается и проходит worker, но отрицательный вердикт выдаёт заглушка, а не AI. Несколько событий/реальные JPEG проверяются синтетическим HTTP-тестом, без добавления тестовых production endpoints.

Создать MOV без банковских данных (существующий файл не перезаписывается автоматически):

```fish
ffmpeg -v error -f lavfi -i testsrc2=size=160x120:rate=10 -t 3 -an -c:v mjpeg /tmp/forteguard-ui-test.mov
```

| Переменная | Назначение |
|---|---|
| `VITE_UI_MODE` | Только `mock` в dev включает синтетику; default/`bridge` — настоящий Backend. Production всегда bridge. Не секрет. |
| `UI_PROXY_TARGET` | Серверная настройка Vite proxy, default `http://127.0.0.1:8001`; не включается в JS. |

Других frontend env-переменных не требуется. **Никаких секретов в `VITE_*`, frontend `.env` или storage.** Не запускайте Vite из терминала с экспортированными серверными секретами. Браузер обращается к относительным `/ui-api/*` с `credentials: same-origin`, HttpOnly-cookie и CSRF-header; адреса production в JS нет. Vite сохраняет Origin (`changeOrigin: false`), поэтому Backend должен разрешать точный `http://localhost:5173`. При смене hostname/порта также измените Origin Backend, не используйте wildcard.

## Устройство

- `App.tsx`: компоновка страницы, загрузка сервисного адаптера.
- `components/UploadCard.tsx`: input, drag-and-drop, замена файла, dev-сценарий.
- `components/AnalysisStatus.tsx`: стадии обработки и ID задания, без выдуманных процентов.
- `components/Results.tsx`: вердикт, события, кадры, место для проверенного нормативного источника.
- `hooks/useAnalysis.ts`: состояния, защита от повторной отправки, отмена, cleanup при unmount/pagehide.
- `lib/analysis.ts`: проверка файла, форматирование, последовательный polling с AbortSignal и общим timeout 5 минут, включая загрузку. Даже зависший адаптер не удерживает UI после таймаута.
- `lib/contracts.ts`: типы и runtime-проверка ответов, ограниченные JPEG data URL, проверка HTTPS-ссылок.
- `services/mock.ts`: только явно выбранный development mock. `services/index.ts` возвращает `null` для входа через `AccessGate` во всех остальных режимах.
- `components/AccessGate.tsx`: восстановление сессии, отдельный код, logout и возврат ко входу после `401`. Код очищается после отправки, не хранится постоянно.
- `services/bridge.ts`: настоящий fetch, CSRF, multipart и безопасные HTTP/network-ошибки. Внутренний текст ошибок Backend не показывается как есть.

Клиент проверяет расширение, непустой файл и размер по аутентифицированной конфигурации Backend (default/mock — 128 МиБ, не параметр train). MIME не заменяет расширение; контейнер проверяет сервер. Один файл за раз. Замена/удаление сбрасывает результат. Ошибки не превращаются в вердикт. Polling ограничен 5 минутами с начала upload, запросы сессии — 10 секундами; Backend отдельно ограничивает приём тела 60 секундами. При `429` надо подождать, автоматической повторной отправки файла нет.

Таймкоды отображаются как `MM:SS` / `HH:MM:SS` с точностью до миллисекунд; меньшая дробная точность округляется только для отображения. Для кадров используется их собственный `timestamp_sec`. Base64 ограничена эквивалентом JPEG 4 МиБ (Backend default), проверяется синтаксис и JPEG-маркеры, ошибки декодирования браузером дают явную заглушку повреждённого доказательства. Все строки выводятся средствами React без HTML-инъекций. Нет внешних шрифтов, изображений, аналитики и AI-вызовов.

## Проверки

```bash
npm test
npm run typecheck
npm run build
npm run test:production
npm audit --audit-level=high
git diff --check
```

Vitest + Testing Library + jsdom проверяют контракт, пользовательские состояния, все mock-сценарии, недоверенные строки/ссылки, изображения, ошибки, таймаут, отмену, unmount и повторную отправку. В jsdom canvas подменяется синтетической JPEG-фикстурой: эти тесты не доказывают декодирование JPEG реальным браузером. `test:production` проверяет уже собранный bundle на отсутствие mock-реализации, доступа к защищённому API и browser storage.

Добавлены только devDependencies: Vitest, Testing Library React/user-event, jsdom и Prettier (для читаемого форматирования), все с MIT-лицензией по установленным package manifests. Лицензии транзитивных пакетов зафиксированы в lockfile; встречаются MIT, MIT-0, ISC, BSD-2/3-Clause, Apache-2.0, BlueOak-1.0.0, CC0-1.0 и CC-BY-4.0. При распространении инструментов сохранять соответствующие notices/атрибуцию. Новых runtime-зависимостей нет.

## Границы TASK 05A и следующий этап

Bridge вызывает общие Backend-сервисы напрямую, не официальный HTTP API с ключом. Реализованы отдельный код, короткая серверная сессия, HttpOnly/SameSite cookie (Secure в production), CSRF/Origin, лимиты входа/upload и доступ только к заданиям своей сессии. Подробные лимиты и ограничения — в Backend README.

Настоящая ML-модель и проверенная нормативная карта не подключены. `ResultViewModel.sources` остаётся внутренней UI-моделью, не расширяющей API жюри; отсутствующее нормативное основание показано явно. Для TASK 05B нужны согласованные ML-контракт, классы/правила, локальный адаптер и проверенные лицензии. В production FakeAnalyzer запрещён, `disabled` заканчивается ошибкой без ложного вердикта. Подключение модели не входит в этот этап.

Production требует HTTPS, раздачи `dist` и проксирования `/ui-api` на одном доверенном origin, независимых серверных секретов и ограничений reverse proxy. Deployment не выполнялся. Истечение/выход/рестарт закрывают доступ к прежним UI-заданиям; logout не отменяет worker. Отмена кнопкой прекращает только клиентское ожидание. После refresh сессия восстанавливается, история/файл — нет. Общий код не обеспечивает персональный аудит пользователей.

Реальные HTTP-запросы через Vite + FastAPI проверяет `backend/tests/http_e2e.py` (инструкция в Backend README); React взаимодействия проверяются в jsdom. HTTP-тест не является браузерным E2E. Все данные тестов синтетические. Проверки качества модели, полного SLA и публичного URL ещё предстоят.
